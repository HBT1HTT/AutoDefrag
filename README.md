# AutoDefrag

Windows 托盘常驻的磁盘碎片整理 / 优化小工具，支持开机自启与每日定时执行。

> 说明：名字里的 “Defrag” 是准确描述；“清理”仅指碎片整理与 SSD 优化，**不会删除任何文件**，也不是注册表/垃圾文件清理器。

## 它做什么

核心动作只有一条：调用 Windows 自带的 `defrag.exe`：

```powershell
defrag.exe <盘符> /O /H
```

- `/O`：按介质类型执行“优化”。机械硬盘做传统碎片整理；SSD 执行 TRIM/优化（不会做无意义的整盘搬移）。
- `/H`：以高优先级运行。
- 探测碎片率时使用只读的 `defrag.exe <盘符> /A`（仅分析，不整理）。

覆盖范围：

- 只处理**本地固定磁盘**（`Win32_LogicalDisk DriveType=3`），不会碰 U 盘、光驱、网络盘。
- 支持一次选择多个盘符，按顺序串行处理（并行整理会互相拖慢寻道）。
- 整理前后各探测一次碎片率，结果写入日志与结果文件。

除 `defrag` 外，程序只读写自己目录下的 `Data/`（配置与结果）和 `Logs/`（日志），以及可选的注册表 `HKCU\...\Run`（开机自启）。

## 组成

| 文件 | 作用 |
|---|---|
| `app.ps1` | 主进程：托盘图标、右键菜单、设置窗体、单实例保护、每日调度、看门狗 |
| `engine.ps1` | 执行引擎：调用 `defrag.exe`、监控 CPU、必要时挂起/恢复 defrag 进程、汇总结果、发通知 |
| `notify.ps1` | 原生 Toast 通知（WinRT），失败时退化为托盘气泡 |
| `run_hidden.vbs` | 静默启动器：开机自启时隐藏 PowerShell 窗口，避免黑框一闪 |

脚本之间只通过“命令行参数 + 结果文件”通信，互不耦合。

## 运行环境

- Windows 10 / Windows 11
- Windows PowerShell 5.1（系统自带，无需安装 PowerShell 7）
- 无需 .NET SDK、无需第三方模块
- **管理员权限**：`defrag.exe` 需要提权。托盘进程本身可以普通权限运行，引擎会通过 `Start-Process -Verb RunAs` 拉起提权进程

## 快速开始

1. 把整个目录放到任意位置（脚本用自身所在目录定位 `Data/`、`Logs/`，可整体搬迁）。
2. 前台启动（会看到控制台窗口，便于观察）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\app.ps1
```

3. 静默启动（无窗口，适合日常使用）：

```cmd
wscript.exe run_hidden.vbs
```

首次启动会自动创建 `Data/` 与 `Logs/`，并写入默认配置；托盘出现后右键图标即可操作。

### 托盘菜单

- **查看磁盘状态**：只读探测各固定磁盘的碎片率与剩余空间
- **清理指定磁盘**：勾选一个或多个盘符后点“开始清理勾选项”
- **设置**：开机自启、CPU 阈值、每日检查时间、通知停留时长
- **查看日志** / **退出**

## 配置

配置保存在脚本目录下 `Data/config.json`，缺失或损坏时自动回退默认值：

```json
{
  "CpuThreshold": 70,
  "DailyTime": "03:00",
  "AutoStart": true,
  "NotificationTimeout": 30
}
```

| 字段 | 含义 | 取值 |
|---|---|---|
| `CpuThreshold` | CPU 触发阈值（%） | 10–100 |
| `DailyTime` | 每日检查时间 | `HH:mm`（24 小时制）；`0` 或 `00:00` 表示“开机后立即静默执行” |
| `AutoStart` | 开机自启（写当前用户 Run 键） | `true` / `false` |
| `NotificationTimeout` | 通知停留时长（秒） | 10–120 |

每日只执行一次：引擎在清理完整结束后写入 `Data/last_run.txt`（当天日期）；当天已执行则跳过，次日自动恢复。若开机时已错过设定时间，会补跑一次。

## CPU 守护

`defrag.exe` 内部的线程无法单独限速，因此程序在整理期间每秒采样一次系统 CPU：

- 连续 `10` 秒高于阈值 → 挂起整个 `defrag` 进程
- CPU 回落后再稳定 `10` 秒 → 恢复进程

挂起/恢复通过 `ntdll.dll` 的 `NtSuspendProcess` / `NtResumeProcess` 实现。这两个是**未文档化的 NT 原生 API**（Windows 长期存在，但与 `kernel32` 公开接口不同，微软不保证未来行为），部分安全软件可能对此敏感。程序只对本次自己拉起的 `defrag.exe` 进程句柄操作。

## 风险与注意事项

- **不是数据恢复/清理工具**：不做删除、不做注册表清理；唯一磁盘写操作来自 `defrag.exe` 的优化过程。
- **耗时可能很长**：机械硬盘碎片化严重时，单盘整理可能持续几十分钟到数小时；期间磁盘会有明显 I/O。
- **SSD 不必频繁优化**：`/O` 对 SSD 是 TRIM 类优化，过于频繁没有收益；建议按需手动执行，或把每日任务留给机械盘。
- **依赖管理员权限**：非管理员运行时引擎会以非 0 退出码快速失败，原因写入 `Logs/engine.log`。
- **进程挂起属于非常规操作**：若程序在挂起期间被强杀，`defrag` 进程可能保持挂起状态，需要手动结束该进程或重启系统；代码已在正常退出路径做恢复兜底，但强杀无法保证。
- **每日一次锁**只认“日期”，同一天内多次手动清理不受限制。
- 通知依赖系统通知中心；关闭通知或使用精简系统时可能看不到 Toast（会退化为气泡）。

## 构建 / 发布

本项目是纯 PowerShell 脚本，**没有编译产物**，不需要 `dotnet`、不需要安装任何 SDK：

- 直接拷贝目录即可使用；
- 如果希望打包分发，可自行压缩为 zip，或用第三方工具（如 `ps2exe`）自行封装；本仓库不提供预编译 exe。

## 故障排查

- **提示启动引擎失败 / 没有整理动作**：确认 UAC 提权被允许，且 `defrag.exe` 未被组策略禁用。
- **日志在哪**：`Logs/app.log`（托盘）、`Logs/engine.log`（引擎）。
- **每日任务没跑**：检查 `Data/last_run.txt` 是否为今天；`DailyTime` 是否为合法格式。
- **托盘图标消失**：程序异常退出时会留下 `Data/app.pid`；再次启动会自动识别僵尸 PID 并接管。
