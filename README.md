# AutoDefrag

Windows 本地固定磁盘定期碎片整理工具的桌面版（WPF + .NET 10），单文件绿色版，目标机无需安装 .NET 运行时。

- 版本：**v1.9.2**（稳定版）
- 发布形态：`win-x64` 自包含单文件（压缩），已嵌入图标
- 可执行文件：`publish/AutoDefrag.exe`

## 1.9.2：无人值守测试修复

- 进度日志改为只消费完整行，修掉半行被截断、后半段变成新行的问题。
- 修复空日志时不显示“暂无运行日志”占位。
- 预览改为先拿任务锁再清空进度日志，避免并发时清空正在运行任务的日志。
- 重写在替换阶段异常时优先用备份回滚，不再删掉备份只报失败。
- 非法磁盘参数不再退化为“全部磁盘”；检查磁盘读取失败会返回非 0 退出码。

## 1.9.1：策略与解析硬化（不改整理算法）

- 大簇卷（>4KB 簇）上，Windows `/A` 的“无需整理”不再作为跳过文件级重写的依据，并在日志/报告中写明。
- 启动 worker 改用 `ArgumentList` 逐项传参；磁盘参数只接受 `A:` 形式的白名单盘符。
- 新增退出码/错误码映射与多语言容错的 `/A` 解析：解析失败只降级为“未知”，不误判成功或无需整理。
- `drive_status.json` 增加 `LastRunAt` / `LastRunStatus` / `LastErrorCode`，检查磁盘时保留历史。
- 结果页与日志不出现“提速 X%”等无法验证的表述。

## 1.9.0：覆盖率真正拉起来 + 机械盘空闲空间合并 + 设置精简

- **覆盖率不再是“只调大单轮上限”**：
  - 数据盘上的 `Program Files` / `ProgramData` 不再整目录排除（只读、被占用、受保护的文件仍逐文件预检跳过）；
  - 分析改为“Windows /A 口径（≤64MB）+ 大文件”两档优先，Runlist 预算不再被一堆小文件吃光；
  - 均衡档 Runlist 上限 12,000 → 100,000，最彻底档 → 300,000；实测同一块 64KB 簇机械盘覆盖率从 **10.2% → 51.4%**（已用数据覆盖率约 78%）。
  - 多轮整理加入“补扫轮”：正常候选跑完后把最小文件降到 1 簇、可回收下限临时放宽，直到收敛或达到轮次上限；64KB 簇盘均衡/最彻底档最小文件门槛放宽到 1 簇。
- **机械盘空闲空间合并（`defrag <盘> /X`）**：
  - 仅机械硬盘生效，SSD/未知介质绝不执行；设置里新增开关（默认开启），门槛自动判断：
    碎片率 ≥5%、空闲空间 ≥10% 且 ≥1GB、空闲碎片度 ≥5%；不满足只写原因，不跑长时间搬移。
  - 顺序：先 `/X` 再搬文件。先重写会把空闲空间重新打散，合并收益会被抵消。
  - 失败处理：非 0 退出码、权限不足（0x89000024）、卷被占用都会标为失败/未成功；`/D /X` 失败会回退为只 `/D`，最终状态标“部分成功”，不会记成成功。
  - 走现有提权 worker、任务互斥、CPU 挂起/恢复、停止标记、进度、日志与报告体系。
- **设置精简**：整理质量三档成为“最小文件 / 单轮上限 / 可回收下限 / 校验 / 轮次 / 时长”的唯一入口，
  删除 7 个单独数值控件与「自定义」卡片；文件碎片率阈值、固态只优化、机械盘空闲合并是独立开关。
  旧配置 `ConfigVersion` 7 → 8：旧「自定义」按数值距离映射到最接近的档位，用户原有阈值/介质策略不丢。
- **实测与口径**（同一块 64KB 簇机械盘 A:）：
  - Windows `defrag A: /A`（管理员，只读）：整理前 **9%**；Windows 原话“大于 64MB 的文件碎片不会计入”。
  - 本程序分析 75,736 个文件、约 950GB，已分析文件碎片率 **0.05%**，卷覆盖率 **51.36%**（已用数据覆盖率约 78%）。
  - 小范围真实重写验证：48MB 测试文件 6 区段 → **1 区段**、7 区段 → **1 区段**，之后候选归零。
  - 结论：9% 与 0.05% 不是同一口径；`/A` 的残留包含 >64MB 文件、MFT/元数据、空闲空间与 Windows 自己的统计方式，
    **不要期待能到 0**；`/X` 是唯一可能影响空闲空间统计的杠杆，需要用户自己点一次。
- 详见 [RELEASE_NOTES.md](RELEASE_NOTES.md) 的 1.9.0 段。

## 1.5.0 新增：整理质量三档 + 多轮整理 + 覆盖率

### 整理设置（新增分组）

- 设置里新增「整理设置」分组，现有“碎片率阈值（1–15%）”整体迁入，语义不变。
- 第一项「整理质量」三档：**最快 / 均衡（默认）/ 最彻底**，选一档会自动套用整组参数：

| 参数 | 最快 | 均衡 | 最彻底 |
|---|---|---|---|
| 最小处理文件 | 256 KB | 32 KB | 4 KB |
| 单轮最多文件 | 20 | 80 | 300 |
| 单轮最多数据 | 4 GB | 16 GB | 32 GB |
| 可回收下限 | 16 MB | 4 MB | 1 MB |
| 碎片率阈值 | 开 10% | 关 10% | 关 5% |
| 整理后校验 | 抽样 3×4MB | ≤2GB 全量，超过抽样 | 全量 SHA256 |
| 多轮上限 | 1 轮 | 3 轮 | 8 轮 |
| 总时长上限 | 30 分钟 | 120 分钟 | 480 分钟 |

- 手动改动任意一项后档位显示「自定义」，不强行改回；把数值改回与某档完全一致时，档位与单选同步恢复。
- 门控：整理方式 =「本程序整理」时可编辑；「Windows 自带整理」整组置灰（系统 defrag 不读这些参数）；「自动」也置灰
  （自动按磁盘簇大小选引擎，只有大簇盘会用内置引擎）。置灰时已保存的配置保留，切回后可继续使用。
- 复制缓冲 1MB → 4MB；校验只提供 Auto / Full / Sample，**不提供“不校验”**。
- SSD 上的大簇卷默认不做文件级重写（避免无谓写入磨损），实际整理走系统优化 `/O`；HDD 才做重写。
  dry-run、进度区、日志都会明确写“跳过文件级重写”，不会让人误以为点了没反应。可在「整理设置」里关闭该保护。
- 进度区、dry-run/整理报告与 `last_result` 新增**覆盖率**（已分析簇 / 总簇），并注明
  “碎片率只代表已分析文件，不是整卷”。

### 多轮整理

- 单次任务可连续多轮：每轮重新扫描候选，受“轮次上限 / 总时长上限 / 停止标记”约束；
  候选不足或某轮零成功时提前结束，不再“只跑一批就结束”。
- 配置版本 `ConfigVersion` 5 → 6：旧配置自动迁移，原有阈值、整理方式、CPU 阈值等不丢；缺失字段补均衡默认值，
  迁移后立即落盘；非法值按范围回落。

> 为什么这样分：最快档用“高碎片 + 大文件 + 高收益”三个门槛压小候选池，单次 1–2 分钟量级；
> 均衡档把旧版单批 40 文件/8GB 翻倍为 80/16GB 并允许 3 轮补扫，单轮约 6–8 分钟；
> 最彻底档降到 4KB/1MB、300 文件/32GB、8 轮全量校验，单轮约 12–15 分钟，建议空闲时使用。
> 估算按机械盘顺序 ~100MB/s、单文件读写+校验约 2.2 倍数据量；实际耗时取决于碎片分布与介质。

## 1.4.3 修复：系统 defrag 的 /A 预检纳入 CPU 守护

- 1.4.2 只覆盖了本程序自己读写文件的阶段；“Windows 自带整理”路径里整理前/后的只读预检 `defrag <盘> /A`
  仍不受守护。
- 1.4.3 把 `/A` 预检接入同一套语义：整机 CPU 每秒采样，连续 10 秒高于阈值就**挂起该 defrag 进程**
  （不是只写日志），回落到阈值以下并稳定 10 秒再恢复，恢复后继续等它跑完并正常解析输出。
- 覆盖入口：界面“立即整理”“检查磁盘”、每日自动整理、`--worker clean`（含 `--minfrag`），以及整理后的
  `/A` 复核；命令行 `--dry-run` 与托盘预览只分析大簇卷、不调用 `/A`，因此不涉及。
- 挂起/恢复写日志（时间、实测 CPU、阈值、第几次、阶段=预检/复核），并计入 `worker_state.json` 与
  `last_result.txt` 的暂停/继续次数；用户点“停止整理”时，被挂起的预检进程先恢复再终止。
- 设置说明补一句“包括整理前和整理后的 /A 分析预检”。

## 1.4.2 修复：CPU 守护没有真正暂停

- 旧实现只在文件级重写的**复制/校验**阶段每 32MB 采样；**分析/枚举、规划、替换、重写后复算**不采样。
- 命中阈值后只写日志，然后“每次检查睡 1 秒就返回”，复制继续推进，不是真正的暂停；
  实测 `worker_state.json` 出现 `Suspended=1 / Resumed=0` 但文件仍在持续写入。
- 1.4.2 改为：整机 CPU（`GetSystemTimes`，每秒采样）**连续 10 秒 > 阈值 → 原地阻塞，不再读写**；
  ≤ 阈值并**稳定 10 秒 → 自动继续**。覆盖分析/枚举（每目录 + 每 256 个文件）、复制/校验（每 32MB）、
  预检、替换后复核、重写后碎片复算；dry-run 也启用。
- 触发/恢复/长时间暂停都写日志（实测值、阈值、阶段、次数）；`worker_state.json` 每秒更新 CPU 与暂停状态，
  `last_result.txt` 记录暂停/继续次数。
- 设置与主界面文案改为“整机 CPU 连续 10 秒高于阈值时暂停，回落稳定 10 秒后继续”；
  并提示阈值应高于平时后台占用，否则会长时间暂停；保存后对下一次整理生效。

## 1.4.1 修复（基于 1.4.0 真实运行日志）

- **任务级互斥**：新增 `Local\AutoDefrag.TaskGate` 命名互斥量。后台整理/检查、界面预览、命令行 dry-run
  执行前都必须拿到锁，同一时间只允许一个任务操作磁盘（跨实例生效）；抢不到时 worker 返回 `exit=3`，
  界面与日志提示“已有另一个整理/检查/预览任务正在运行，本次未启动”。异常退出由系统自动释放，不留死锁。
- **单实例唤起**：再次双击 exe 时会向已有实例发送“显示主窗口”请求并重试（最多 6×150ms），
  并记录“已请求已有实例显示主窗口”或“已有实例未响应”，避免“点了没反应”；`--tray` 静默启动仍不唤起窗口。
- **dry-run 汇总文案**：不再出现 `碎片 19.3% -> --`，改为 `碎片 19.3% → 未改动（dry-run，整理后未测量）`，
  并修正 `A::` 双冒号。
- **位图失败澄清**：`FSCTL_GET_VOLUME_BITMAP` 可能返回 `ERROR_INVALID_FUNCTION`（非管理员或受保护进程，
  本机实测提权进程也可能遇到）。计划只依赖文件区段与卷几何，不依赖位图；日志/报告明确写
  “空闲布局未知（未能读取卷位图）”，并显示当前进程是否管理员。
- **覆盖率口径**：报告与日志新增 `覆盖率: 已分析簇 / 总簇（%）`，注明“碎片率只代表已分析文件的区段，
  不代表整卷碎片”（小于 8 簇的文件、系统/加密/稀疏文件不纳入分析）。

- 展开/收起状态写入 `config.json`（`ProgressExpanded`），重启保持；展开时窗口自动加高 206 DIP（屏幕空间不足时只加到可用高度），不改动磁盘列表高度。
- 空闲时不再显示进度条：收起态只显示“就绪”；无任务时展开态同样显示“就绪”。
- 停止/中止时强制进入不确定态并最终收敛为“就绪”，不会卡在某个百分比。
- 进度口径：本程序整理按 `已处理字节 / 候选总量`（文件内复制/校验阶段实时更新）计算；调用 Windows `defrag.exe` 时解析其输出中的百分比，解析不到就显示不确定态（动画），不显示假进度；dry-run/预览也走同一套进度通道。

### 整理方式新增“自动”档

- 设置里“整理方式”变为三档：`本程序整理` / `Windows 自带整理` / `自动（推荐）`，默认 **自动**。
- 自动规则按每块盘的存储块大小：**大于 4KB → 本程序整理**（文件级重写）；**不超过 4KB → Windows 自带整理**（`defrag.exe`）。
- 主界面与进度区显示每块盘本轮实际采用的方式与依据，例如 `自动 → 本程序整理（存储块 64KB，大于 4KB）`、`自动 → Windows 自带整理（存储块 4KB，不超过 4KB）`。
- 计划日志、进度日志、`Data/rewrite_report.txt` 与 `last_result` 都会记录该决策（配置值 + 实际方式 + 判断依据），不只记录结果。
- 旧配置兼容：v1.3.0 已保存过 `EngineMode` 的配置**保留原选择**；v1.2.0 及更早的配置没有该字段，读取后按“自动”处理（≤4KB 盘仍是系统整理，行为不突变）。配置版本 `ConfigVersion = 5`。

## 1.3 新增：大簇卷（>4KB）支持

Windows 自带的 `defrag.exe` 在 64KB/128KB 簇卷上基本无效（`/A` 返回 0%、整理 1 秒结束）。1.3 起：

- **小簇卷（≤4KB）**：仍调用系统 `defrag.exe`，行为与 1.2.0 完全一致。
- **大簇卷（>4KB）**：碎片率与空闲布局由程序自己算（卷位图 + 文件 Runlist），实际整理改用**文件级重写**：
  选碎片最多的文件 → 复制到卷内新分配的连续位置 → 大小+SHA256 校验 → 还原 ACL/时间戳/属性/ADS → 原子替换 → 释放旧空间。
- 设置里可选**整理方式**：`本程序整理` / `Windows 自带整理` / `自动（推荐，默认）`（详见 1.4 说明）。选择持久化，重启保持。
  在大簇卷上选择“Windows 自带整理”时，运行结果会明确写“系统方式无效（该磁盘）”，不会静默报成功。
- 设置里可选**整理范围**：只整理碎片较多的文件（文件级碎片率达到阈值，1–15%，默认 10%）或全部整理（默认）。
  阈值只作用于文件自身碎片率，不是整卷；它与“单批 40 文件 / 8GB”“回收不足 4MB 跳过”等规则叠加生效，未达阈值的文件会在日志/报告里记“未达碎片率阈值”。
- 跳过：正在使用、系统关键（`$MFT`/`$LogFile`/pagefile/hiberfil/注册表 hive/WinSxS/系统目录）、
  稀疏/压缩/加密/重解析点、硬链接、只读、路径过长、收益太小（可回收不足 4MB）的文件；跳过原因写入报告。
- 单文件独立事务，失败只影响该文件、保留原文件；不并行搬大文件，可随时“停止整理”（当前文件做完后停）。
- 结果口径：**比整理前干净，但不承诺 0 碎片**（64KB 簇的最小单位就是 64KB，必然有零头）。

### 新引擎（本程序整理）与原有功能对照

| 功能 | 大簇卷（文件级重写）下的表现 |
|---|---|
| 每日调度 / 当天首次启动补跑 | 完全一致：仍由主界面调度器触发，按整理方式交给 worker |
| 托盘菜单（暂停/恢复自动整理、打开主界面、设置、退出） | 完全一致；额外新增“停止整理”“预览整理（不动磁盘）” |
| CPU 占用守护 | 语义一致，实现方式不同：系统方式挂起 `defrag.exe`；本引擎没有子进程，改为在复制/校验循环中暂停读写，等 CPU 回落再继续（次数写入 `last_result` 的暂停/继续字段） |
| 完成/失败通知 | 一致，通知文案带“成功/失败/跳过”与碎片率变化 |
| 手动“立即整理”与中止 | 一致；“停止整理”写停止标记，当前文件做完后停，已完成的文件不回滚 |
| 按盘勾选、勾选即时保存 | 一致 |
| 开机自启 / 静默启动 | 一致 |
| 日志与 last_result | 一致，并额外写入 `Data/rewrite_report.txt`（每个文件前后 extent、跳过原因），不含文件内容 |
| 整理中状态显示 / 按钮禁用 | 一致，状态行显示“正在整理第 i/n 个文件” |
| 只读碎片率 | 大簇卷改为自算（系统 `defrag /A` 对大簇卷返回 0% 不可信） |


## 功能

- **极简主界面**：只有磁盘勾选列表 + 底部可折叠进度区 + “查看日志” + “立即整理”。外观、自动整理、运行选项都在右上角“设置”打开的独立窗口里。
- **磁盘多选**：勾选/取消后立即写入配置，下次启动保持；不会出现“操作一次就丢失状态”。
- **磁盘信息通俗化**：类型直接显示“机械硬盘 / 固态硬盘 / 类型未知”，第二行显示文件系统与每块大小（如 `NTFS · 每块 4KB`），右侧分两行显示“可用 x GB / 共 y GB”。窗口 560×550，最小 480×360，100%/125%/150% 缩放下上述文字均完整显示。
- **按介质选择参数**：自动识别 HDD / SSD。
  - 机械硬盘：`defrag <盘> /D /H` 做传统碎片整理（真正合并碎片）；若碎片率 ≥ 10% 且空闲空间 ≥ 10%，追加 `/X` 合并空闲空间，即 `defrag <盘> /D /X /H`。
  - 固态硬盘（以及无法识别介质的磁盘）：只调用 `defrag <盘> /O` 做按介质优化/TRIM，不做全盘整理，避免额外写入影响寿命。
  - `/D`、`/O` 互斥，按介质二选一；`/H` 只对机械硬盘有意义。只读分析始终单独使用 `defrag <盘> /A`，不与整理参数混用。
- **结果判定不看退出码，看证据**：
  - 退出码为 0 且有错误码、或退出码非 0 → `失败`；
  - 退出码为 0 但输出为空、或运行时间不足 5 秒 → 不认成功；
  - 超大存储块（> 4KB）的卷看不到实际整理过程 → `可能不支持`；
  - 机械硬盘读不到碎片情况、又看不到实际整理过程 → `无法确认`；
  - 其余才记为 `成功`。
  - 结果写入 `%LocalAppData%\AutoDefrag\Data\last_result.txt`，含每块盘的状态、退出码、暂停/继续次数、整理前后碎片率。
- **CPU 守护**：采样**整机** CPU（`GetSystemTimes`，每秒一次，与任务管理器同源）。整机占用连续 10 秒高于阈值时暂停读写：系统方式挂起 `defrag.exe`；文件级重写方式在**分析/枚举、复制、校验、替换、复核**各阶段原地等待，回落到阈值以下并稳定 10 秒后自动继续。触发/恢复都写日志（实测值、阈值、阶段、次数），并记录到 `worker_state.json`/`last_result.txt`。阈值可在设置里调整（默认 70%，范围 10–100%）；阈值应高于平时的后台占用，否则会长时间暂停。
- **每日调度**：可设置每天几点整理（24 小时制，如 `03:00`）；也支持“当天还没整理的话，启动后自动整理一次”。执行完成后写入当日锁，同一天不会重复自动整理。
- **托盘常驻**：关闭窗口默认最小化到托盘。托盘菜单：打开主界面、设置…、立即整理、暂停/恢复自动整理、查看日志、退出；菜单文字随状态实时更新。
- **外观**：跟随系统的浅色/深色主题，也可手动指定；支持选择界面字体（列系统已安装字体，选中立即生效并保存）。
- **开机自启**：写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（值名 `AutoDefrag`），指向当前 exe，带 `--tray` 参数静默启动。
- **日志与结果**：运行数据目录（`%LocalAppData%\AutoDefrag`）下的 `Logs/app.log`（主进程）、`Logs/engine.log`（后台任务）、`Data/last_result.txt`、`Data/worker_state.json`、`Data/drive_status.json` 均可用于排查。

## 使用

1. 双击 `AutoDefrag.exe` 启动（主界面为普通权限，不会一启动就弹 UAC）。
2. 在磁盘列表中勾选要维护的磁盘，点“立即整理”。
3. 点“立即整理”时 Windows 会请求管理员权限：这是 `defrag.exe` 执行整理所必需的；取消授权则本次不执行。
4. 关闭窗口默认最小化到托盘；需要彻底退出时用托盘菜单的“退出”。
5. 右上角“设置”可调整：界面字体、界面主题、**整理方式（本程序 / Windows 自带 / 自动）**、
   **整理设置（整理质量三档 / 碎片率阈值 / 单轮与多轮参数 / 校验方式 / SSD 只优化）**、
   每天自动整理、当天首次启动补跑、每天几点、开机自启、关闭窗口最小化到托盘、整理完成提示音、CPU 占用上限。保存后立即生效。
6. 主界面底部进度区：小箭头展开可看实时日志与阶段/文件/速度；日志面板跟随深浅主题，时间戳弱化、警告/错误/暂停/恢复/完成按语义着色；收起状态与展开状态都会被记住。

### 预览整理（dry-run，不动磁盘）

想先看看会怎么整理，可以在命令行跑一键预览。它只读分析，不建托盘、不开主窗口、不改任何文件：

```powershell
AutoDefrag.exe --dry-run                             # 所有 >4KB 固定磁盘
AutoDefrag.exe --dry-run --drives "A:"               # 指定卷
AutoDefrag.exe --dry-run --path "A:\MyDir"           # 只分析一个目录（小规模验证）
AutoDefrag.exe --dry-run --path "A:\MyDir" --quiet   # 不弹结果对话框
```

结果写入 `Data/rewrite_preview.txt`：卷几何、碎片率与覆盖率、候选排序与理由；读不到卷位图时明确写
“空闲布局未知（未能读取卷位图）”，计划仍按文件区段与卷几何生成。
想真的整理同一个目录：把 `--dry-run` 换成 `--rewrite`（会复制并替换文件，务必先在测试目录试）。

托盘菜单也有“预览整理（不动磁盘）”，只对大簇卷生效。

### 数据与配置

- 运行数据固定在 `%LocalAppData%\AutoDefrag`：`Data/config.json`、`Data/last_run.txt`、`Data/last_result.txt`、`Data/drive_status.json`、`Data/worker_state.json`、`Data/progress.log`、重写报告与预览、停止标记，以及 `Logs/app.log`、`Logs/engine.log`。
- **exe 同目录不再产生任何文件或目录**：可以把 `AutoDefrag.exe` 单独放到桌面/任意目录，旁边不会出现 `Data`、`Logs`。
- 从旧版（≤1.6.0）升级：首次启动会把 exe 同目录原有的 `Data`/`Logs` 迁移到新位置（含引擎方式、整理质量、CPU 阈值、勾选磁盘、调度、主题、字体、进度区展开状态等），迁移完成后清理旧目录；迁移结果写日志。
- 若 `%LocalAppData%` 不可写，会依次降级到用户临时目录、最后回退 exe 同目录；降级会写警告日志、在底部状态行提示并弹出托盘通知，不会静默失败。
- 旧版 PowerShell 版本的 `Data/config.json` 可直接读取；缺少的新字段使用默认值，原有值保留（当前 `ConfigVersion = 7`，启动时自动迁移 v5/v6→v7）。

### 命令行（内部使用）

同一个 exe 支持 worker 模式，供主进程提权调用，一般无需手动使用：

```
AutoDefrag.exe --worker clean --drives "C:,A:" --threshold 70
AutoDefrag.exe --worker status
```

## 注意事项与风险

- **首次启动可能立即开始整理**：默认“每天自动整理”开启、时间为 `03:00`，首次运行还会默认勾选全部本地固定磁盘。若当前时间已过 `03:00` 且当天尚未执行，启动后会立刻开始一次整理。建议首次启动前先在设置里取消不需要的磁盘，或关掉“每天自动整理”，观察后再执行。
- **64KB 存储块的卷现在可以真正整理**：1.3 起大簇卷改用文件级重写（复制→校验→原子替换），不再依赖 `defrag.exe`。系统自带的 `defrag.exe` 对这类卷仍然无效，所以设置里选“Windows 自带整理”时会直接提示“系统方式无效（该磁盘）”。
- **默认整理方式为“自动”**：新安装或旧配置里没有 `EngineMode` 字段时按自动处理（大簇盘走文件级重写，≤4KB 盘走系统整理）；1.3.0 保存过具体选择的配置会保留原选择，不会被悄悄改成自动。自动的实际选择与依据会写进日志、进度区和 `last_result`。
- **文件级重写会读写整个文件**：默认只在机械硬盘上做重写；固态硬盘的大簇卷按「固态硬盘只做系统优化」跳过重写（可在整理设置里关闭该保护）。建议在空闲时执行；正在使用/系统关键文件会被跳过，不会强行处理，因此结果只是“明显更干净”，不是 0 碎片。
- **整理质量决定覆盖与耗时**：最快档只处理大且碎的文件，耗时最短；最彻底档会纳入很小的文件并多轮扫描、全量校验，耗时最长。只想快速缓解卡顿时选最快，空闲时追求干净选最彻底。
- **碎片率阈值只作用于文件**：勾选“只整理碎片较多的文件”后，未达阈值的文件会保留原样并在报告里记“未达碎片率阈值”；调高阈值更快，但零头会更多。
- **128KB 存储块未实测**：代码不假设簇大小，但没有 128KB 卷的实机数据；建议先 dry-run 看报告。
- **“无法确认”不是失败**：判定需要“有输出且运行时间 ≥ 5 秒”作为证据。容量很小、瞬时完成的卷可能因证据不足记为 `无法确认`，可结合日志里的命令与输出判断。
- 整理耗时取决于磁盘容量、碎片情况与介质类型：SSD 通常很快，机械硬盘可能持续很久。请避免在关键工作或移动办公时运行，笔记本请保持供电。
- 同一磁盘请勿同时运行多个整理工具（例如同时运行本程序与其他碎片整理软件），以免互相争抢卷锁。
  本程序内部已加任务级互斥：同一时间只允许一个整理/检查/预览任务运行，重复触发会被拒绝并提示。
- CPU 守护会在高负载时**暂停**：系统方式挂起 `defrag.exe`；文件级重写在分析、复制、校验、替换、复核阶段原地等待（不再读写）。任务管理器里可看到进程 CPU/磁盘读写明显下降，属于预期行为；日志会记录"暂停/仍在暂停/继续"。
- 每日执行锁按“当天是否已执行”记录；删除 `Data/last_run.txt` 会导致下次启动重新判定当天是否需要执行。
- 本程序调用 Windows 自带的 `defrag.exe`，不包含第三方磁盘驱动；对磁盘的写操作由系统组件完成。
