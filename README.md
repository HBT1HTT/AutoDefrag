# AutoDefrag

Windows 本地固定磁盘定期碎片整理工具的桌面版（WPF + .NET 10），单文件绿色版，目标机无需安装 .NET 运行时。

- 版本：**v1.2.0**
- 发布形态：`win-x64` 自包含单文件（压缩），已嵌入图标
- 可执行文件：`publish/AutoDefrag.exe`（70,026,097 字节，约 66.8 MB）

## 功能

- **极简主界面**：只有磁盘勾选列表 + “查看日志” + “立即整理”。外观、自动整理、运行选项都在右上角“设置”打开的独立窗口里。
- **磁盘多选**：勾选/取消后立即写入配置，下次启动保持；不会出现“操作一次就丢失状态”。
- **磁盘信息通俗化**：类型直接显示“机械硬盘 / 固态硬盘 / 类型未知”，第二行显示文件系统与每块大小（如 `NTFS · 每块 4KB`），右侧分两行显示“可用 x GB / 共 y GB”。窗口 560×470，最小 480×360，100%/125%/150% 缩放下上述文字均完整显示。
- **按介质选择参数**：自动识别 HDD / SSD。
  - 机械硬盘：`defrag <盘> /D /H` 做传统碎片整理（真正合并碎片）；若碎片率 ≥ 10% 且空闲空间 ≥ 10%，追加 `/X` 合并空闲空间，即 `defrag <盘> /D /X /H`。
  - 固态硬盘（以及无法识别介质的磁盘）：只调用 `defrag <盘> /O` 做按介质优化/TRIM，不做全盘整理，避免额外写入影响寿命。
  - `/D`、`/O` 互斥，按介质二选一；`/H` 只对机械硬盘有意义。只读分析始终单独使用 `defrag <盘> /A`，不与整理参数混用。
- **结果判定不看退出码，看证据**：
  - 退出码为 0 且有错误码、或退出码非 0 → `失败`；
  - 退出码为 0 但输出为空、或运行时间不足 5 秒 → 不认成功；
  - 超大存储块（> 4KB）的卷看不到实际整理过程 → `可能不支持`；
  - 机械硬盘读不到碎片情况、又看不到实际整理过程 → `无法确认`；
  - 其余才记为 `成功`。
  - 结果写入 `Data/last_result.txt`，含每块盘的状态、退出码、暂停/继续次数、整理前后碎片率。
- **CPU 守护**：系统 CPU 持续高于阈值 10 秒时临时暂停 `defrag.exe`，回落到阈值以下 10 秒后自动继续；阈值可在设置里调整（默认 70%，范围 10–100%）。
- **每日调度**：可设置每天几点整理（24 小时制，如 `03:00`）；也支持“当天还没整理的话，启动后自动整理一次”。执行完成后写入当日锁，同一天不会重复自动整理。
- **托盘常驻**：关闭窗口默认最小化到托盘。托盘菜单：打开主界面、设置…、立即整理、暂停/恢复自动整理、查看日志、退出；菜单文字随状态实时更新。
- **外观**：跟随系统的浅色/深色主题，也可手动指定；支持选择界面字体（列系统已安装字体，选中立即生效并保存）。
- **开机自启**：写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（值名 `AutoDefrag`），指向当前 exe，带 `--tray` 参数静默启动。
- **日志与结果**：`Logs/app.log`（主进程）、`Logs/engine.log`（后台任务）、`Data/last_result.txt`、`Data/worker_state.json`、`Data/drive_status.json` 均可用于排查。

## 使用

1. 双击 `AutoDefrag.exe` 启动（主界面为普通权限，不会一启动就弹 UAC）。
2. 在磁盘列表中勾选要维护的磁盘，点“立即整理”。
3. 点“立即整理”时 Windows 会请求管理员权限：这是 `defrag.exe` 执行整理所必需的；取消授权则本次不执行。
4. 关闭窗口默认最小化到托盘；需要彻底退出时用托盘菜单的“退出”。
5. 右上角“设置”可调整：界面字体、界面主题、每天自动整理、当天首次启动补跑、每天几点、开机自启、关闭窗口最小化到托盘、CPU 占用上限。保存后立即生效。

### 数据与配置

- 优先使用 exe 所在目录：`Data/config.json`、`Data/last_run.txt`、`Data/last_result.txt`、`Data/drive_status.json`、`Logs/app.log`、`Logs/engine.log`。
- 若 exe 所在目录不可写（例如放在 `Program Files`），自动回退到 `%LocalAppData%\AutoDefrag`。
- 旧版 PowerShell 版本的 `Data/config.json` 可直接读取；缺少的新字段使用默认值，原有值保留（当前 `ConfigVersion = 3`）。

### 命令行（内部使用）

同一个 exe 支持 worker 模式，供主进程提权调用，一般无需手动使用：

```
AutoDefrag.exe --worker clean --drives "C:,A:" --threshold 70
AutoDefrag.exe --worker status
```

## 构建

需要 Windows 10/11 x64 与 .NET 10 SDK：

```powershell
dotnet publish -c Release src/AutoDefrag/AutoDefrag.csproj -o publish -p:EnableCompressionInSingleFile=true
```

版本号来自 `src/AutoDefrag/AutoDefrag.csproj`（当前 `1.2.0`）。产物为 `publish/AutoDefrag.exe` 单文件，自包含、已嵌入图标，无 trimming。

## 注意事项与风险

- **首次启动可能立即开始整理**：默认“每天自动整理”开启、时间为 `03:00`，首次运行还会默认勾选全部本地固定磁盘。若当前时间已过 `03:00` 且当天尚未执行，启动后会立刻开始一次整理。建议首次启动前先在设置里取消不需要的磁盘，或关掉“每天自动整理”，观察后再执行。
- **64KB 存储块的卷可能不受支持**：存储块大于 4KB（例如 64KB）的卷，Windows 自带的 `defrag.exe` 往往无法实际整理。本程序会照常尝试，但不会误报成功：看不到整理过程时状态为 `可能不支持`，界面也会用一行提示说明。建议看日志确认真实结果。
- **“无法确认”不是失败**：判定需要“有输出且运行时间 ≥ 5 秒”作为证据。容量很小、瞬时完成的卷可能因证据不足记为 `无法确认`，可结合日志里的命令与输出判断。
- 整理耗时取决于磁盘容量、碎片情况与介质类型：SSD 通常很快，机械硬盘可能持续很久。请避免在关键工作或移动办公时运行，笔记本请保持供电。
- 同一磁盘请勿同时运行多个整理工具（例如同时运行本程序与其他碎片整理软件），以免互相争抢卷锁。
- CPU 守护会在高负载时**暂停** `defrag.exe`，属于预期行为；任务管理器里可能看到该进程暂停。
- 每日执行锁按“当天是否已执行”记录；删除 `Data/last_run.txt` 会导致下次启动重新判定当天是否需要执行。
- 本程序调用 Windows 自带的 `defrag.exe`，不包含第三方磁盘驱动；对磁盘的写操作由系统组件完成。
